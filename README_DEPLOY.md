# راهنمای انتقال GLADIATOR از Railway به Vercel

## چه چیزی تغییر ک


1. **از polling به webhook**: روی Railway ربات دائم در حال polling بود. Vercel سرورلسه
   و پروسه‌ی دائمی نداره، پس ربات الان با webhook کار می‌کنه (تلگرام خودش هر آپدیت
   رو به `/api/webhook` پوش می‌کنه).
2. **از SQLite به Postgres**: فایل‌سیستم Vercel بین اجراها پاک می‌شه، پس `bot_data.db`
   دیگه کار نمی‌کرد. همه‌چیز رفت روی Postgres (پیشنهاد: Neon، از تب Storage در Vercel).
3. **حالت‌های موقت (مثل "منتظر دسته‌بندی" یا "ادمین در حال پاسخه") از حافظه (`context.user_data`)
   منتقل شد به جدول `pending_states` توی همون دیتابیس** — چون حافظه بین درخواست‌های
   سرورلس مشترک نیست.
4. قابلیت‌های جدید: منوی 🎭 حالت ناشناس / ⚔️ چالش‌ها، چالش روزانه، `/mystats`، و
   پیام‌های زمان‌دار (⏱ حذف خودکار بعد از ۱ / ۶ / ۲۴ ساعت).
5. توکن هاردکد شده از `config.py` حذف شد. **حتماً توکن قبلی رو توی BotFather Revoke کن.**

هیچ‌کدام از قابلیت‌های قبلی (دسته‌بندی پیام، گفتگوی ادامه‌دار، بلاک/آنبلاک، آمار ادمین) حذف نشده.

## مراحل دیپلوی

### ۱. ساخت دیتابیس Postgres
- توی داشبورد Vercel پروژه رو بساز، برو تب **Storage → Create Database → Postgres (Neon)**.
- بعد از ساخت، Vercel خودش متغیر `POSTGRES_URL` یا `DATABASE_URL` رو به پروژه وصل می‌کنه.

### ۲. متغیرهای محیطی (Project Settings → Environment Variables)
| متغیر | مقدار |
|---|---|
| `BOT_TOKEN` | توکن جدید از BotFather (توکن قبلی رو Revoke کن، لو رفته بود) |
| `ADMIN_IDS` | آیدی عددی ادمین‌ها با کاما جدا شده |
| `DATABASE_URL` | اگر Vercel خودکار ست نکرد، از Neon کپی کن |
| `WEBHOOK_SECRET` | یک رشته تصادفی دلخواه (مثلاً از `openssl rand -hex 20`) |
| `CRON_SECRET` | یک رشته تصادفی دیگر، برای محافظت از `/api/set_webhook` و `/api/cron` |

### ۳. دیپلوی
ریپازیتوری رو به Vercel وصل کن (Import Project از GitHub) و دیپلوی کن. جداول دیتابیس
خودشون در اولین اجرای webhook ساخته می‌شن (`init_db`).

### ۴. ثبت Webhook در تلگرام (فقط یک بار، بعد از هر دیپلوی موفق)
توی مرورگر باز کن:
```
https://<دامنه-پروژه‌ات>.vercel.app/api/set_webhook?token=<CRON_SECRET>
```
اگر خروجی `"ok": true` گرفتی، ربات آماده‌ست. تستش کن: به ربات پیام بده.

### ۵. تنظیم پاکسازی پیام‌های زمان‌دار (مهم)
Vercel روی پلن Hobby معمولاً Cron Job رو فقط یک‌بار در روز اجرا می‌کنه، که برای
حذف "بعد از ۱ ساعت" کافی نیست. `vercel.json` یک کرون ساعتی تعریف کرده، ولی اگر
پلنت اجازه نداد، این راه رایگان رو انجام بده:
- برو به [cron-job.org](https://cron-job.org) (رایگان)، یک Job بساز که هر ۵ تا ۱۰ دقیقه
  این آدرس رو GET بزنه:
  ```
  https://<دامنه-پروژه‌ات>.vercel.app/api/cron?token=<CRON_SECRET>
  ```
- نکته: حتی بدون این کرون هم، هر بار که کاربر یا ادمین پیامی بفرسته، ربات به‌صورت
  فرصت‌طلبانه پیام‌های سررسیده رو پاک می‌کنه. کرون فقط دقت زمان‌بندی رو بیشتر می‌کنه.

## تست لوکال (اختیاری، قبل از دیپلوی)



```bash
pip install -r requirements.txt
export BOT_TOKEN=...
export ADMIN_IDS=...
export DATABASE_URL=postgresql://...
python local_polling.py
```

## نکات امنیتی
- توکن قدیمی ربات توی گیت‌هاب پابلیک بود — **همین الان Revoke کن.**
- `WEBHOOK_SECRET` و `CRON_SECRET` رو حتماً پر کن، وگرنه هرکسی می‌تونه اندپوینت‌های
  `/api/webhook` یا `/api/cron` رو صدا بزنه.
